# 1. 기획 — 가능성 검토와 구현 계획

## 배경

PC에서 마크다운 파일만 따로 볼 일이 많은데, 쓸 만한 전용 뷰어가 많지 않다.
아크로뱃 리더가 PDF를 "보기만" 하듯, `.md`를 더블클릭하면 바로 깔끔하게 열리는 프로그램을 만든다.
특히 **Obsidian 볼트의 노트**(위키링크, 임베드, 콜아웃 등)가 제대로 보여야 한다.

## 가능성 판단

충분히 가능하다. 핵심은 "마크다운 → HTML 변환 + 내장 브라우저(WebView2)로 표시"이며,
편집기보다 훨씬 단순하다.

- 가능: Obsidian 문법 대부분 (위키링크, 임베드, 콜아웃, 하이라이트, 주석, 태그, 수식, Mermaid, 프론트매터)
- 핵심 난제: 링크 해석 — 파일 위쪽에서 `.obsidian` 폴더를 찾아 볼트 루트로 보고, 파일 이름으로 대상을 찾는다
- 불가/제한: Dataview·Templater 등 **플러그인 실행 결과** → 코드 블록으로만 표시

## 기술 선택

| 후보 | 판단 |
|---|---|
| **C# / .NET 8 WPF + WebView2 + markdown-it** | ✅ 채택. WebView2는 Windows 10/11 기본 탑재, 가볍고 기존 환율 위젯과 같은 계열 |
| Tauri (Rust) | 더 작지만 학습 부담 |
| Electron | 메모리가 무거워 제외 |

렌더링 보조: KaTeX(수식), Mermaid(다이어그램), highlight.js(코드), DOMPurify(보안), CodeMirror 6(편집).

> 처음 계획은 C# 쪽 Markdig였으나, Obsidian 확장 문법을 한 곳에서 다루기 위해
> 렌더링은 JS(markdown-it + 자체 플러그인)로 옮겼다.

## 단계별 계획 (원안)

1. **MVP** — 파일 연결, 기본 렌더링, 라이트/다크, 자동 새로고침
2. **Obsidian 대응** — 볼트 인식, 위키링크, 임베드, 콜아웃
3. **읽기 편의** — 목차, 찾기, 수식·Mermaid·코드 하이라이트, 확대, 뒤로가기
4. **마무리** — 탭, 최근 파일, 인쇄/PDF, 설치 파일

## 처음부터 챙긴 점

- 마크다운 안의 HTML/스크립트는 걸러낸다 (DOMPurify)
- 한글 경로·파일명, 한글 폰트 기본값(Pretendard → 맑은 고딕)
- 인코딩 자동 판별 (UTF-8 / UTF-16 / CP949)
